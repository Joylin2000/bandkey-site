3App Store Connect 配置步骤

3.1 创建订阅群组（Subscription Group）

  • App Store Connect → App 内购买项目 → 订阅 → 新建群组 BandKey Premium（订阅组内的商品互斥，用户只能订一个）

3.2 创建订阅商品

  • 群组内新建：bandkey.monthly（月）、bandkey.yearly（年）
  • 每个商品填写：显示名称（Band Key 月度 / Band Key 年度）、本地化描述、价格点、审核截图（订阅条款页截图）
  • 终身买断放 非消耗型 App 内购买项目：bandkey.lifetime，与订阅分开

3.3 本地化

  • 至少提供 简体中文 与 英文 两套名称/描述（与应用商店本地化一致）

3.4 订阅优惠（可选）

  • 免费试用：7 天（仅年付开放，月付不开放，避免快速取消循环）
  • 优惠码 / 首年折扣：上线后从后台按需发放

3.5 审核所需材料

  • 订阅条款与说明截图（含价格、周期、续订规则）
  • App 内购买项目的审核截图（显示订阅入口与价格）
说明：所有 App 内购买项目都需在「App 内购买项目」管理页提交审核，且需有审核沙盒账号可测试流程；配置完成后要等苹果审核通过，订阅商品才可销售。

4技术接入方案（无后端）

Band Key 无后端，订阅状态必须在设备本地完成验证。Capacitor 8 / iOS 15+ 下两条可行路线：

方案方式优点代价推荐度
A. StoreKit 2 原生桥接 写一个 Swift 原生插件（Capacitor 自定义 Plugin），用 Transaction.currentEntitlements + AppTransaction 本地验证订阅 零第三方依赖、零服务费、苹果签名验证最安全、完全可控 需要写 Swift 桥接代码（约 200-300 行）；跨设备同步需用户手动恢复购买 首选
B. RevenueCat（官方 Capacitor 插件） 接入 @revenuecat/purchases-capacitor，由 RevenueCat 托管价格/优惠/状态 几乎不写原生代码；试用/优惠/恢复开箱即用；跨设备自动同步；后台可视化 引入第三方 SDK 与账号；免费层限 1 万月活用户；依赖其服务可用性 备选

方案 A 关键实现点

  • Capacitor 自定义插件暴露方法：getEntitlements()、purchase(productId)、restore()、listenForUpdates()
  • 用 Product.PurchaseOption 发起购买；Transaction.updates 监听续订/退款事件
  • 解锁判断：Transaction.currentEntitlements 中存在对应 productId 且 expirationDate 未过期
  • 本地持久化：订阅状态缓存到 UserDefaults，启动时快速判断 UI，后台再异步刷新
  • 前端（www）通过 window.__cbApi 或 Capacitor 事件总线对接，无需改动现有原型逻辑
无论哪条路线，前端 UI 只是展示层：真正的解锁校验必须落在原生 Swift 侧（本地验证 entitlement），防止被篡改。

5合规与审核要点

  • 恢复购买：设置页必须提供「恢复购买」按钮，调用 restore()（苹果强审项）
  • 订阅条款：购买页需展示价格、周期、续订与取消规则（苹果强制）
  • 试用说明：若有免费试用，需明示试用结束后的收费方式与取消路径
  • 隐私：订阅购买信息属敏感数据；隐私政策需补充订阅/购买数据说明（可在现有 privacy-policy.html 增补一节）
  • App 内购买项目能力：需在 iOS 工程 Signing & Capabilities 添加 In-App Purchase capability，并确保 Provisioning Profile 含该能力（需在开发者后台更新 profile）
  • 审核演示：审核员需能在沙盒环境走通 订阅→解锁→恢复 全流程，建议在文档里附测试账号说明
